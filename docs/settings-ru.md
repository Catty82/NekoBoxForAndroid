# Настройки (Settings) — справочник пунктов

Документ описывает экран **Настройки** в NekoBox for Android: что означает каждый пункт и когда его обычно меняют. Структура совпадает с разделами в приложении (`global_preferences.xml`).

> Многие изменения требуют **перезагрузки прокси-сервиса**; смена уровня логов — **перезапуска приложения**.

---

## 1. Настройки приложения

### Автоматическое подключение
Если прокси был запущен до перезагрузки телефона или обновления приложения, сервис попытается включиться снова после старта. Удобно, чтобы VPN/прокси поднимался сам после перезагрузки.

### Тема
Цветовая тема интерфейса. После смены тема применяется сразу (активность пересоздаётся); при запущенном сервисе он тоже перезагружается.

### Ночной режим
Как включать тёмную тему:
- **Использовать системную тему** — как в Android
- **Включить** — всегда тёмная
- **Отключить** — всегда светлая
- **Авто** — по расписанию/условиям приложения

### Сервисный режим
Как работает прокси:
- **VPN** — системный VPN: перехватывает трафик приложений через виртуальный интерфейс (обычный режим)
- **Только прокси** — без VPN; приложениям нужно вручную указывать локальный SOCKS/HTTP-порт

При смене режима запущенный сервис останавливается.

### Реализация TUN
Движок виртуального сетевого интерфейса (только в режиме VPN):
- **gVisor** — пользовательский стек (часто стабильнее на «капризных» устройствах)
- **System** — системный TUN
- **Mixed** — смешанный режим

Меняйте, если есть проблемы с UDP, играми или совместимостью.

### MTU
Максимальный размер пакета на VPN-интерфейсе. По умолчанию часто `9000` (jumbo); стандартный вариант — `1500`. Долгое нажатие позволяет задать своё значение. Слишком большой MTU может ломать некоторые сети; слишком маленький — чуть снижать скорость.

### Интервал обновления уведомлений о скорости
Как часто обновлять скорость в уведомлении: выкл. / 500 мс / 1 с / 3 с / 10 с.  
При значении **Выключить** статистика профиля по трафику тоже становится недоступной.

### Статистика трафика профиля
Считать и показывать объём трафика по профилям. Если выключено — использованный трафик не учитывается.

### Показать прямую скорость
В уведомлении рядом со скоростью через прокси показывать скорость **прямого** (bypass) трафика.

### Показывать название группы в уведомлении
В постоянном уведомлении сервиса отображается имя группы активного профиля.

### Всегда показывать адрес
На карточке конфигурации всегда виден адрес сервера (а не только имя профиля).

### Подсказка о соединении с лимитным тарифным планом
Подсказать Android, что VPN — «лимитная» сеть (metered). Система может ограничить фоновые обновления. Доступно на Android 9+.

### Использовать WakeLock
Держать CPU активным, пока работает сервис. Может помочь при обрывах в глубоком сне, но сильнее расходует батарею.

### Тип журнала
Уровень подробности логов ядра: `none` → `warn` → `info` → `debug` → `trace`.  
Для повседневной работы достаточно `warn`/`info`; `debug`/`trace` — для диагностики.  
Долгое нажатие — размер буфера логов (КБ). Требуется перезапуск приложения.

### Пользовательская конфигурация
Глобальный JSON, который дополняет/переопределяет конфиг sing-box. Для продвинутых пользователей; неверный JSON может сломать запуск.

## 2. Настройки маршрута

### Режим VPN для приложений
Открывает список приложений: какие идут через VPN/прокси, а какие — мимо (proxy / bypass). Нужен режим **VPN**.

### Обход LAN
Локальные/частные адреса (LAN) не гонятся через VPN-интерфейс на стороне Android (маршруты VPN). Обычно нужно, чтобы локальные устройства (принтер, NAS, роутер) оставались доступны напрямую.

### Обход LAN в ядре
Тот же смысл, но правило обхода LAN добавляется **внутри sing-box**. Имеет смысл, когда обхода только на уровне VPN недостаточно или вы в режиме «только прокси».

### Включить анализ трафика (Traffic Sniffing)
Определение реального домена/протокола по содержимому пакетов (когда приложение ходит на IP):
- **Выключенный** — sniffing нет
- **Перехватывать результат для Маршрутизации** — домен используется для правил маршрутизации
- **Результат проверки для адрес назначения** — sniffing ещё и подменяет/задает destination (как override)

Полезно для правил по доменам, когда приложения резолвят DNS сами.

### Определить адрес назначения
Если назначение — домен, резолвить его по стратегии IPv6 перед отправкой. **Конфликтует с FakeDNS**.

### Маршрут IPv6
Поведение IPv6:
- **Отключить**
- **Включить**
- **Предпочитать**
- **Исключительно** (только IPv6)

Влияет на dual-stack и стратегию выбора адресов.

### Поставщик ресурсов правил
Откуда брать базы `geoip`/`geosite` (и аналоги) для правил маршрутизации:
- Official
- Loyalsoldier (soffchen/sing-geosite)
- Chocolate4U/Iran-sing-box-rules
- L11R/Antizapret-sing-box-geo

Выбирайте набор под свой регион и набор правил.

## 3. Настройки DNS

### Удаленный DNS
DNS для трафика, идущего **через прокси** (по умолчанию DoH Google: `https://dns.google/dns-query`). Можно указать DoH/DoT/UDP DNS в формате, который понимает ядро.

### Правило домена для Удаленного
Стратегия выбора A/AAAA при резолве Remote DNS: `auto`, `prefer_ipv6`, `prefer_ipv4`, `ipv4_only`, `ipv6_only`.

### Прямой DNS
DNS для **прямого** (bypass) трафика (по умолчанию `https://223.5.5.5/dns-query`). Обычно ставят «домашний» или региональный резолвер.

### Правило домена для Прямого
Та же стратегия IP, но для Direct DNS.

### Правило домена для Адреса сервера
Как резолвить адрес **самого прокси-сервера** (до подключения к узлу).

### Включить маршрутизацию DNS
Домены из правил обхода резолвить через Direct DNS. Удобно для локальных/обходных сайтов, но есть риск **утечек DNS**, если правила настроены неаккуратно.

### Включить FakeDNS
Подмена DNS «фейковыми» IP, чтобы sniffing/маршрутизация видели домен. Часто нужно для корректных правил по доменам в VPN. После остановки прокси некоторые приложения могут требовать перезапуск сети/приложения. Конфликтует с «Определить адрес назначения».

## 4. Входящие настройки

### Порт прокси SOCKS5
Локальный mixed-порт (SOCKS/HTTP) приложения. Другие программы на устройстве могут подключаться к `127.0.0.1:<порт>`.

### Добавить HTTP-прокси к VPN
На Android 10+ система может получать HTTP-прокси из VPN. Браузеры и часть приложений пойдут через HTTP-прокси **минуя** виртуальный NIC — иногда быстрее/проще для HTTP(S).

### Разрешить подключения из локальной сети
Слушать входящие не только на `127.0.0.1`, а на `0.0.0.0`: другие устройства в Wi‑Fi смогут использовать этот телефон как прокси. **Не включайте в ненадёжных сетях** без понимания рисков.

## 5. Прочие настройки

### URL-адрес проверки подключения
Адрес для URL Test / проверки доступности узлов (по умолчанию `http://cp.cloudflare.com/`).

### Включить Clash API
Поднять Clash API и панель YACD на `127.0.0.1:9090` (переключение узлов, просмотр соединений и т.п.). В меню приложения появляется соответствующий пункт.

### Сбросить исходящие соединения при изменении сети
При смене Wi‑Fi ↔ мобильная сеть сбрасывать исходящие коннекты ядра, чтобы быстрее восстановить работу.

### Сбросить исходящие соединения при выходе из спящего режима
То же после пробуждения устройства — помогает после долгого сна, когда старые сокеты «залипли».

### Всегда разрешать небезопасные
Глобально ослабить проверку TLS-сертификатов для узлов (как Allow Insecure везде). **Снижает безопасность** — только если осознанно нужно.

### Отключить проверку сертификатов при обновлении подписок
При скачивании подписок не проверять HTTPS-сертификат источника. Удобно для самоподписанных зеркал; риск MITM при обновлении списка узлов.

### Минимальная версия TLS протокола
Минимальный TLS при запросах подписок: `1.2` или `1.3`.

### Показать нижнюю панель, как в SagerNet
Классическая нижняя навигация в стиле SagerNet вместо текущего варианта UI.

## Краткая шпаргалка «что трогать»

| Задача | Куда смотреть |
| --- | --- |
| Не поднимается после перезагрузки | Автоматическое подключение |
| Не открывается локальный NAS/роутер | Обход LAN / Обход LAN в ядре |
| Правила по доменам не срабатывают | Анализ трафика + FakeDNS |
| Нужен прокси для других устройств в Wi‑Fi | Разрешить подключения из LAN + порт прокси |
| Только выбранные приложения через VPN | Режим VPN для приложений |
| Много обрывов при смене сети/сне | Сброс соединений + при необходимости WakeLock |
| Отладка | Тип журнала → `debug`/`trace` |
